# 《霸凌王》Bully King

一款用「換位思考」做職場霸凌防治教育訓練的互動網頁遊戲。玩家扮演職場中的某個角色，目標是「成為霸凌王」——一路做出看似合理、甚至很有效率的管理決策；直到最終審判，才從受影響者的證詞與全程隱藏的數據中，看見這些決策真正造成的傷害。

- **目前版本**：v1.30.3（2026-10-02）
- **使用範圍**：大豐環保科技內部教育訓練教材，尚未對外公開發布
- **遊玩時間**：短劇本約 2～3 分鐘，長劇本約 3～5 分鐘

---

## 快速開始

用瀏覽器直接開啟 `《霸凌王》.html` 即可遊玩。

- 單一 HTML 檔，劇本、邏輯、樣式都在同一個檔案裡；不需要安裝、建置或伺服器
- 圖片放在 `assets/images/`，必須和 HTML 保持相對路徑，才能正常顯示
- 手機與電腦都能玩
- `index.html` 是與主檔內容完全相同的複本，給 GitHub Pages 當入口用

## 一輪遊戲的流程

```text
序幕（抽出本輪詞條）
  → 日常情境（短劇本 4 個／長劇本 8 個，從角色題庫隨機抽）
     其中隨機穿插「合理化檢查」（短劇本 2 次／長劇本 3 次）
  → 固定高潮事件
  → 反差時刻（期中揭露）
  → 兩難場景（申訴、約談或質詢）
  → 最終審判（三段配角證詞 + 隱藏數據揭曉）
  → 結局（按「繼續」後，才顯示人格分析報告、結局圖鑑與稱號牆）
```

## 核心機制

### 雙軌數值

- **明數值（三圍）**：畫面上方即時顯示，每位角色語意不同，例如葉經理是「威嚴／績效／服從度」
- **隱藏數值**：恐懼、毒性、風險、安全感等，全程不顯示，到最終審判才一次揭曉，並決定結局

### 命運骰與被害者視角

較嚴重的選項會強制跳出「被害者視角」畫面，由玩家「擲下命運骰」（1～6 點）。點數越大，這個選擇的數值效果放大得越多。

### NPC 臨界點與連續選擇偵測

- 對同一位配角累積太多傷害，會觸發「臨界點」，之後的互動與稱號判定都會改變
- 連續 3 次選同一類型的選項，系統會跳出提示

### 旗標回呼

前面做過的關鍵選擇會被記住，之後在高潮、兩難等固定事件中被重新提起。

### 本輪詞條（Roguelite）

每輪開局隨機套用一個限定規則，共 10 種：雙重命運骰、玻璃心全開、如履薄冰、一觸即發、零容忍、眾矢之的、心裡有數、八卦擴散、回音室、年終考核季。每種都有專屬的剪紙詞條卡，在序幕畫面圖文並排顯示。

### 解鎖內容

| 內容                                            | 解鎖條件                                                                                               |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 地獄模式（New Game+）                           | 該角色完成任意一輪。開啟後隱藏數值增幅 ×1.2，選項改用包裝過的中性話術，考驗玩家能不能認出偽裝過的霸凌 |
| 隱藏情境（每位角色 1 則）                       | 該角色完成一輪地獄模式                                                                                 |
| 跨角色客串（葉經理、徐課長、老陳、吳董各 1 則） | 完成指定的另一位角色一輪                                                                               |
| 角色：阿迪／曾組長／小雨                        | 分別需要任 2／3／4 名角色完成過地獄模式；其餘四位角色一開始就能選                                      |

### 結局、稱號與成就

- **結局**：每位角色 6 + 1 種（A～F，加上隱藏結局 G），共 49 種，分成三個家族：
  - **黑暗**（A～D）
  - **覺醒**（E）
  - **向上**（F～G）
- **稱號**：依人格分析判定，每位角色 5 種、共 35 種，各有專屬徽記，會記錄在稱號牆
- **成就**：14 個跨角色成就，在成就牆顯示徽章，未解鎖的以灰階顯示；已解鎖的成就與稱號徽記都可以點擊放大（另備 1024 px 的 `_lg.webp` 高解析版，點開才載入）
- **圖庫**：成就牆的第三個分頁，收藏已拿到的結局圖（49 張）與遇見過的人物（主角 7、主要配角 21、客串人物 9）；未解鎖的顯示「？？？」，點圖片可用高解析版放大

結局門檻是用數千輪隨機遊玩模擬校準的，目標是讓 A～F 各約一到兩成，G 約 4～5%。

## 設計原則：終旨是「成為霸凌王」

這是最高優先的設計準則，新增任何內容或系統前都要先對照：

- **狠心的路永遠比較好走。** 強硬、冷處理、甩鍋等選項在明數值上通常更快見效；健康的選項在結構上就是比較難、回報比較慢。這正是真實職場霸凌文化會延續下去的原因。
- **不為好行為設計獎勵捷徑。** 詞條、模式、養成系統只能增加難度，不能變成「當好人比較划算」的外掛。
- **代價延後出現。** 傷害藏在隱藏數值、配角心裡話與最終審判裡，不在做選擇的當下提醒玩家。
- **遊戲中不說教。** 玩法說明集中在首頁的「❓ 怎麼玩」，遊玩過程不插入教學文字；首頁說明以不劇透為原則。

## 開發者模式

在首頁「🔒 開發者模式」按鈕上，2.5 秒內連點 10 下即可進入。共有四個分頁：

1. **數值調整台**：檢視、覆寫任何角色／情境／選項的數值加減
2. **成就條件說明**
3. **結局條件說明**：列出每位角色結局的實際判定順序與門檻
4. **稱號條件說明**

數值覆寫會存在瀏覽器裡，可以匯出／匯入 JSON。目前採用的覆寫檔放在 `assets/數值調整覆寫檔/bkw_overrides_v1.json`。

> 修改結局門檻時，`computeEnding()`（實際判定）和 `devEndingConditions()`（開發者模式說明）兩處必須同步。用覆寫檔調過數值的角色，門檻要用「套用覆寫後」的數值重新模擬校準。

## 存檔與清除紀錄

所有跨輪紀錄只存在這台裝置的瀏覽器裡（localStorage），不會上傳到任何伺服器：

| 鍵值                    | 內容                                           |
| ----------------------- | ---------------------------------------------- |
| `bkw_meta_v2`         | 各角色完成輪數、結局圖鑑、稱號牆、地獄模式紀錄 |
| `bkw_achievements_v1` | 成就解鎖紀錄                                   |
| `bkw_overrides_v1`    | 開發者模式的數值覆寫                           |

換瀏覽器、使用無痕視窗或清除網站資料，紀錄都會消失。首頁右下角的「🗑 清除遊戲紀錄」可以手動清空，按下後會先跳確認視窗。

## 維護流程

### 修改遊戲內容

1. 只改 `《霸凌王》.html`
2. 更新檔案開頭的 `CURRENT_VERSION` 並在 `CHANGELOG` 新增紀錄（版本號規則見下方）
3. 做語法檢查：
   ```bash
   node -e "const h=require('fs').readFileSync('《霸凌王》.html','utf8');[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].forEach(m=>new Function(m[1]));console.log('ok')"
   ```
4. 把主檔複製成 `index.html`。GitHub Pages 讀的是 `index.html`，忘了複製的話，網站會停留在舊版

### 版本號規則

- **v1.X**：一輪新功能或一批新內容
- **v1.X.Y**：同一輪的後續微調與修正

### 接入新圖片

1. 正式圖為 1536 × 1024 的 PNG，轉成寬 800 px 的 WebP（首頁主視覺用 1200 px；稱號徽記這類透明方形小圖用 256 px，ffmpeg 會保留透明背景）：
   ```bash
   ffmpeg -i 原圖.png -vf "scale=800:-1" -q:v 75 輸出.webp
   ```
2. 在事件物件加上 `banner:'assets/images/events/xxx.webp'`
3. 有 banner 的卡片，只把標題與開場文字包在 `.scene-image-zone` 裡，選項、數據等其餘內容放在圖片區外；否則圖片左右會出現黑邊、文字也看不清楚
4. 接入後確認所有圖片路徑都對應到實際檔案

### 部署

- **正式環境**：公司 OHS Portal 的 `frontend/public/training/bullyingking2026/`
  1. 先 `git pull`
  2. 把主檔複製成 `index.html`，並同步 `assets/images/`
  3. 重新加上左上角的「← 教育訓練」返回連結（主檔沒有這段，每次複製都會被覆蓋掉）
  4. 推送到 `main` 後，Coolify 會自動部署
- **備份倉庫**：`l80623-gloomy/bully-king`，保存完整的開發歷程與素材
